# dsh-opencode

Один живой провайдер **OpenCode** для [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness).

Harness несёт замороженный каталог моделей OpenCode внутри адаптера pi-ai, а
каждый настроенный маршрут pi-ai может назвать ровно один протокол — поэтому
смешанный каталог OpenCode либо не растёт, либо требует по провайдеру на каждый
интерфейс. Этот плагин делает правильно:

* регистрирует **свой единственный провайдер** (`opencode-live`, имя «OpenCode»),
  адаптер которого обслуживает все импортированные модели с любым протоколом
  (OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, Google
  Generative AI);
* добавляет **диалог импорта** в Настройки → Модели: он читает живой каталог
  OpenCode Zen / Zen Go, предзаполняет интерфейс и контекст модели из
  установленного каталога pi-ai или models.dev, и просит выбрать интерфейс
  только для моделей, о которых метаданных нет;
* **маршрутизирует каждый диалог по его сессии**. Запрос с идентификатором
  сессии harness маршрутизируется по нему (обёртка OpenCode в pi-ai сама
  добавляет `x-opencode-session`), поэтому у каждого диалога свой ключ
  маршрутизации на шлюзе; запрос без сессии откатывается к значению `sessionId`
  из конфигурации, которое требует OpenCode Go (`400 MissingSessionID`), а
  `forceSessionHeader: false` отключает и этот запасной вариант;
* **передаёт изображения**. Вложение чата хранится harness как долговечная
  ссылка; адаптер проецирует её в точную версию запроса (масштаб в пределах
  бюджета пикселей, перекодирование в пределах бюджета байт) и отправляет байты
  в image-форме этого протокола (image-часть OpenAI, image-блок Anthropic или
  Google inline data part), со стабильным «handle» перед ними.

После импорта штатные маршруты `opencode` / `opencode-go` удаляются
(`retireShipped`, по умолчанию включено), поэтому в выборе модели остаётся ровно
одна группа OpenCode.

## Установка

```
plugin_manager(action: "install_bundle", target: "<абсолютный путь к этому репозиторию>")
```

Плагин рассчитан на DeepSeek Harness 0.2.2-rc.1 (`engines.dsh` —
`>=0.2.2-rc.1 <0.3.0-0`). Он зависит от `@earendil-works/pi-ai` (та же библиотека,
что у harness); `install_bundle` ставит её в профиль. Зависимость закреплена на
версиях, которые поставляет этот релиз — pi-ai 1.3.0 и schemastery ~3.19.0, —
потому что плагин импортирует pi-ai напрямую и берёт свою копию из этого
checkout'а: обновление, встроенное в host, до неё не доходит без подъёма пина.
`application: applied` — плагин работает. Строка в Host — `include:opencode`;
после правки кода плагина переустановите его (`remove_bundle`, затем
`install_bundle`), чтобы подменились модули.

Ключ: сохраните ключ OpenCode под `OPENCODE_API_KEY` или
`OPENCODE_GO_API_KEY` (страница «Модели» или окружение). Список моделей
публичный, поэтому импорт работает и без ключа; запросы будут падать, пока ключ
не сохранён.

## Использование

1. **Настройки → Модели → OpenCode** (карточка провайдера плагина).
2. Нажмите **«Проверить модели»**.
3. Каждая модель появится с предзаполненным интерфейсом и окном контекста. Для
   моделей, чей интерфейс определить не удалось, нужно выбрать интерфейс
   (пресеты: OpenAI Chat Completions / OpenAI Responses / Anthropic Messages /
   Google Generative AI) и окно контекста (по умолчанию 1000000) — до этого
   кнопка импорта заблокирована. Ненужные модели снимите галочкой.
4. Нажмите **«Импортировать выбранные»**. Импортированные модели по умолчанию
   **включены**; карточка покажет «импортировано N · включено M» и список
   управления, где каждую модель можно включить или отключить. Провайдер
   предлагает только включённые модели, поэтому список выбора остаётся ровно
   таким, каким вы его оставили. В списке управления есть **поиск по названию
   или id**, **фильтр источника** (Все / Go / Zen) и метка источника у каждой
   модели — видно, идёт ли включённая модель через подписку OpenCode Go или
   через Zen; «Включить все» / «Отключить все» действуют на видимые строки —
   так можно привести в порядок одно семейство моделей. У каждой модели есть
   **шестерёнка**: она открывает встроенный редактор **окна контекста**,
   **максимума токенов**, **интерфейса** и **типов входа** (флажки **Текст** /
   **Изображение**, хотя бы один обязателен). Пустое поле сбрасывает это
   значение к стандартному, а **«Сбросить к стандартным»** возвращает всё из
   снимка каталога, зафиксированного при импорте (`defaults`); рядом с полями
   видны эти стандартные значения. «Применить» в менеджере сохраняет набор
   включённых, у редактора свои «Применить» / «Сбросить». Оба применяются сразу.
5. Отключение не удаляет модель: метаданные и интерфейс остаются сохранёнными,
   поэтому повторный импорт для включения не нужен.

`GET /opencode/status` (и карточка) показывает последний импорт, число
сохранённых и включённых моделей, состояние регистрации и проверку первой
включённой модели.

## Как это работает

| Часть | Что делает |
|---|---|
| `lib/catalogue.js` | Читает оба шлюза, убирает дубли по id (побеждает первый target), отсекает внутренние id, разрешает каждую модель: установленный каталог pi-ai → models.dev → неразрешённая (диалог спросит). Модели Gemini, например `gemini-4-argon`, разрешаются в Google Generative AI, как и любой другой протокол, и больше не опускаются. |
| `lib/adapter.js` | LLM-адаптер плагина: один маршрут, смешанные протоколы. Стриминг делегируется штатному провайдеру OpenCode из pi-ai, поэтому диспетчеризация по `model.api`, совместимости и обёртка с заголовком сессии переиспользуются. Конвертирует диалог harness в контекст pi-ai и поток событий pi-ai обратно в StreamChunk harness; ответ, в котором финальные аргументы вызова инструмента не разобрались, отклоняется с `MALFORMED_RESPONSE` вместо запуска инструмента с пустыми аргументами `{}`. |
| `lib/images.js` | Проекция изображений для адаптера: превращает долговечные ссылки в версии запроса нужного маршрута через смонтированный сервис вложений, формирует текст-«handle» для модели, считает бюджет base64 на запрос и собирает ошибку `IMAGE_OFFLOAD_REQUIRED`, на которую harness отвечает выгрузкой самых старых изображений. |
| `lib/import-store.js` | Проверяет выбор из диалога, дополняет недостающие endpoint'ы по пресету шлюза и протокола и считает разницу с сохранённым каталогом (imported / updated / removed). |
| `lib/plugin.js` | Регистрирует адаптер и запись в каталоге настраиваемых провайдеров, применяет импорт через settings-шов, удаляет штатные маршруты и обслуживает `/opencode/catalogue`, `/opencode/import`, `/opencode/status`. |
| `client.js` | Диалог импорта в карточке «Моделей» (RU/EN). |

Протоколы разрешаются во время чтения каталога: установленный каталог pi-ai
авторитетно указывает протокол, models.dev — для id новее установленного релиза,
а небольшая таблица-фолбэк покрывает непубличные модели шлюза, которых нет ни в
одном публичном каталоге (`qwen3.7-max` → Anthropic Messages, контекст 1M /
вывод 64k; `omen-alpha` → OpenAI Chat Completions, 500k / 128k — по документации
OpenCode Go и общественным каталогам Go). Диалог предлагает те же четыре
протокола в пресетах. В выбор интерфейса попадает только действительно
неизвестный id; любое предзаполненное значение можно переопределить или сбросить
шестерёнкой у модели.

Провайдер наследует собственное поведение pi-ai 1.3.0. Воспроизведённое
рассуждение другой модели отбрасывается, а не превращается в видимый текст;
строгий tool-запрос Anthropic повторяется без предпочтительных strict-инструментов,
когда API отклоняет его по грамматике или размеру; изображения внутри
результатов tool-ошибок Anthropic выносятся из них, а не отправляются inline; а
поток OpenAI-совместимого протокола может расположить рассуждение перед текстом.

## Изображения

Журнал сессии хранит прикреплённое изображение как долговечную ссылку, а не
байты. Если выбранная модель принимает изображения (это задаёт редактор
**типов входа** у модели), адаптер проецирует каждую живую ссылку через сервис
вложений harness в детерминированную версию запроса:

- размеры вписываются в `requestImageMaxPixels` (по умолчанию 4 Ми пикселя,
  пропорции сохраняются, увеличения нет), байты перекодируются в пределах
  `requestImageMaxBytes` (по умолчанию 1 МиБ). Сервис кэширует результат для
  пары «ссылка + цель», поэтому повторные ходы переиспользуют одну версию;
- перед каждым изображением идёт стабильный «handle» (`Image <имя> (<sha256>);
  request preview <w>x<h>px.`), чтобы модель могла на него ссылаться, а при
  наличии отображения host-путей вложений в мир инструментов — ещё и
  read-only путь нормализованной копии;
- модель только с текстом никогда не получает байты: harness заменяет каждое
  вхождение текстом-заглушкой ещё до вызова адаптера;
- вхождение, помеченное harness как offloaded, становится текстом-заглушкой:
  длинный диалог сохраняет записанную историю, не отправляя старые изображения
  снова;
- если удержанные изображения превышают `maxRequestImageBytes` (по умолчанию
  20 МиБ base64), запрос падает с `IMAGE_OFFLOAD_REQUIRED` и числом самых
  старых вхождений, которые надо опустить; штатный плагин выгрузки изображений
  записывает это решение в сессию и повторяет запрос. Значение `0` отправляет
  все изображения без ограничения.

Для изображений нужен сервис `attachments` harness — базовая поставка его
монтирует; сервис нужен только пока читается живое изображение, поэтому уже
выгруженная история всё равно отрисовывает заглушки (с read-only путём
нормализованной копии, когда он доступен). Ссылка, байты которой получить
нельзя (например, сессия перенесена из поставки, хранившей вложения иначе),
заменяется заглушкой с указанием нечитаемого вложения, а не ломает ход. Три
бюджета действуют на весь маршрут провайдера, а не на отдельную модель.
Изображения в выводе ассистента не входят в chat-replay pi-ai и отклоняются.

## Конфигурация

Все поля необязательны и живые; `models` пишет диалог импорта.

```yaml
- id: opencode
  name: dsh-opencode
  config:
    provider: opencode-live       # id маршрута плагина (смена — с перезагрузкой)
    displayName: OpenCode         # имя в выборе модели
    targets: [opencode-go, opencode]  # шлюзы; первый побеждает при дублях
    apiKeyEnv: OPENCODE_API_KEY   # ссылка на ключ
    targetApiKeyEnv:              # ссылки по шлюзам
      opencode: OPENCODE_API_KEY
      opencode-go: OPENCODE_GO_API_KEY
    sessionHeader: x-opencode-session
    sessionId: dsh-opencode       # запасное значение для запросов без сессии
    forceSessionHeader: true      # отправлять его, даже если сессии нет
    includeFree: true             # оставлять варианты `-free`
    exclude: []                   # подстроки id, которые не показывать
    retireShipped: true           # удалять штатные маршруты после импорта
    endpoints:
      opencode: https://opencode.ai/inference
      opencode-go: https://opencode.ai/inference/go
    catalogueUrl: https://models.dev/api.json
    catalogueTimeoutMs: 90000
    cacheDir: ""                  # пусто: <profile>/.dsh-opencode
    timeoutMs: 15000
    requestImageMaxPixels: 4194304  # бюджет пикселей одного изображения в запросе
    requestImageMaxBytes: 1048576   # бюджет закодированных байт одного изображения
    maxRequestImageBytes: 20971520  # бюджет base64 всех изображений запроса; 0 — без выгрузки
    models: []                    # сохранённый каталог (строки несут `enabled` и `defaults`)
```

Блок `endpoints` следует каноническим корням шлюзов pi-ai 1.3.0. Прежние корни
`/zen` по-прежнему отвечают, и их можно вернуть через `endpoints`; уже
импортированные строки сохраняют base URL, зафиксированный при импорте. Модель,
не заявившая ёмкость, получает стандарт DSH 0.2.2 для пользовательских моделей:
1 000 000 контекста и 128 000 токенов вывода.

## Host API

Маршруты того же origin с cookie-аутентификацией:

- `GET /opencode/catalogue?refresh=1` →
  `{ ok, fetched, resolved, models, unknown, presets, warnings }`; строка модели —
  `{ id, name, api|null, apiLabel|null, baseURL|null, contextWindow|null,
  maxTokens|null, input, source, resolved, suggestedApi }`.
- `POST /opencode/import`, тело `{ models: [{ id, name, api, baseURL?,
  contextWindow?, maxTokens?, input?, source?, enabled? }] }` →
  `{ ok, imported, updated, removed, total, enabled, skipped, retired,
  registered, models, importedAt }`. Новая модель включается, если явно не
  указано `enabled: false`; ранее отключённая остаётся отключённой.
- `POST /opencode/enabled`, тело `{ enabled: string[] }` — точный набор id
  моделей, которые провайдер предлагает →
  `{ ok, enabled, disabled, total }`. Всё импортированное, чего нет в списке,
  становится отключённым и не удаляется.
- `POST /opencode/model` — настройки одной модели. `{ id, reset: true }`
  возвращает окно контекста, максимум токенов, интерфейс и типы входа из снимка
  `defaults`; `{ id, contextWindow?, maxTokens?, api?, input? }` задаёт
  переопределения, где `null` сбрасывает одно поле к стандартному (смена
  интерфейса пересчитывает `baseURL` от корня шлюза; `input` — непустой список
  из `text` и/или `image`). Ответ — `{ ok, model }` в форме строки статуса.
- `GET /opencode/status` → состояние провайдера, полный список сохранённых
  моделей с полями `source`, `enabled`, действующими `contextWindow` /
  `maxTokens`, `input` (что принимает модель: `text`, `image` или оба) и
  снимком `defaults`, `stored` / `enabledCount`,
  зарегистрированные id провайдеров, разрешённая модель-пример (первая
  включённая) и последний импорт.

## Проверка

- `npm test` — 83 юнит-теста, без сети.
- Живая проверка адаптера (один провайдер, реальный ключ OpenCode Go): OpenAI
  Chat Completions (`glm-5.2`), Anthropic Messages (`claude-haiku-5-5`) и OpenAI
  Responses (`gpt-6-luna`) успешно стримились. Теперь адаптер обслуживает четыре
  протокола — Google Generative AI добавлен вместе с pi-ai 1.3.0, и живые шлюзы
  предлагают модели Gemini (`gemini-4-argon` на обоих), — но записанная проверка
  покрывает остальные три.
- Живая проверка изображения: изображение, отправленное через адаптер, дошло до
  Chat Completions-маршрута шлюза как `image_url` data-часть (перед ней шёл
  текст-«handle», с заголовком сессии и bearer-ключом), и шлюз принял запрос.

## Известные ограничения

- Штатная страница «Модели» перечисляет всех «спящих» провайдеров каталога pi-ai
  в списке добавления провайдера. После удаления штатных маршрутов OpenCode
  карточка плагина убирает списанные id (`opencode`, `opencode-go`) из этих
  списков выбора, поэтому OpenCode предлагается ровно один раз. Это правка DOM
  чужого списка: страница показывает спящих провайдеров независимо от того, кто
  ими владеет, и точки расширения для фильтра у неё нет.
- Изображениям нужны сервис вложений harness и модель, у которой в **типах
  входа** отмечено `image`; сам адаптер поддерживает изображения во всех четырёх
  протоколах. Изображение в сообщении ассистента или system/developer по-прежнему
  отклоняется с `UNSUPPORTED_CONTENT`: chat-replay pi-ai его не представляет.
- Дубли id между шлюзами разрешаются в пользу первого в `targets`.
- Аутентифицированный список Zen фильтруется по правам аккаунта; импорт
  зеркалит то, что аккаунт может вызвать.
